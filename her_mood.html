这里定义发给 Jev 的问题（题目、类型、选项/档位）以及每个档位对应的答案（心情增减、她的回应）。游戏按这份配置出题、结算，并原样展示 Jev 返回的概率分布与置信度。

选「真实 Jev」后，「探知」会把 {state, model, questions}（Choice 题）发给模型并展示返回的概率分布；你选完回应后再发一次 Score / Noul 题给行动打分。任何一步失败都会回退本地启发式，并在判决面板里显示具体原因。
官方端点是 https://api.typesafe.ai/v1/systemone（systemone 中间没有连字符——旧版错写成 system-one 正是截图里 400 的原因之一，已保存的旧端点会自动纠正）。请求体为 {state, model, questions}。
实测结论：官方 API 不放行任何浏览器跨域来源——OPTIONS 预检一律 400 且不返回 Access-Control-Allow-Origin（从浏览器页面直接发起的请求一律被拒——无论以 file 方式打开、本地 dev server，还是官方 console 域名）。所以 live 模式必须经由代理转发，把代理地址填到上面的端点框即可；本地模式不受影响，开箱即玩。
展开：两种自备代理的做法（复制即用）
① 本地 Python 代理（推荐，零依赖，随游戏附带的 jev_proxy.py）：运行 python jev_proxy.py，再把端点填为脚本启动时打印的地址（形如 http://localhost:8010，可用 --port 改端口）。脚本只转发、不记录 Key。
② Cloudflare Worker（免费、长期在线）：新建一个 Worker，粘贴下面代码并部署，然后把 Worker 地址（如 https://xxx.workers.dev）填为端点——Key 仍填在下方，由浏览器发给 Worker 再转发： 
export default {
  async fetch(req) {
    const CORS = {
      "Access-Control-Allow-Origin": "*",
      "Access-Control-Allow-Methods": "POST, OPTIONS",
      "Access-Control-Allow-Headers": "Content-Type, Authorization"
    };
    if (req.method === "OPTIONS") return new Response(null, { headers: CORS });
    const resp = await fetch("https://api.typesafe.ai/v1/systemone", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": req.headers.get("Authorization") || ""
      },
      body: await req.text()
    });
    const h = new Headers(resp.headers);
    Object.entries(CORS).forEach(([k, v]) => h.set(k, v));
    return new Response(resp.body, { status: resp.status, headers: h });
  }
};
Jev 要求请求体必须携带 model 字段，默认 jev-latest；也可填具体版本号（见官方文档 Models 页）。
不必先保存：用当前填写的端点 / Key / 请求头发一个最小 Noul 请求，直接看通不通、错在哪。
仅保存在当前页面内存中，刷新即清除，不会上传到任何第三方。
留空则默认使用 Authorization: Bearer 你的 Key。可按接口需要自定义。
角色（role）：want=她想要什么（Choice，探知阶段发送，返回的概率分布就是她的「底牌」）；mood=情绪档位（Score，结算阶段发送，其 score 决定心情增减）；modifier=附加判断题（Noul，结算阶段发送）。每题需指定唯一 id。
